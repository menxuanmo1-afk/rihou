# iPhone AI 助理：个人试用版服务

状态：代码已准备；**尚未部署，尚未连接真实 DeepSeek 调用**。先验证个人手机，再设计商店公开分发的账号和费用机制。这个版本的访问码不适合发给所有商店用户共用。

## 先记住三件事

- DeepSeek 密钥只放在 Cloudflare 的加密 Secret 里，不能发到聊天、放进 GitHub 或填到 App。
- App 只需要 Worker HTTPS 地址和你另设的服务访问码。启用 AI 前必须主动同意发送时间记录及备注；未连接时只做本机统计。
- 提前 10 分钟的计划通知由 iPhone 本地安排，与 Worker 和 DeepSeek 无关。系统权限、专注模式、通知摘要等可能影响到达方式，不能保证绕过系统限制。

## 稍后一起部署

1. 在自己浏览器里登录 Cloudflare 和 DeepSeek 开放平台。确认 API 余额及可用模型。在 Cloudflare 部署这个文件夹，不是 GitHub 网页文件夹。
2. 在本目录运行 `npx wrangler@4 login`，再运行 `npx wrangler@4 deploy`。此时缺少 Secret 的接口会返回 503，不会调用模型。
3. 依次执行以下命令，在隐藏输入提示里填写，不把值写进命令或文件：

   ```sh
   npx wrangler@4 secret put DEEPSEEK_API_KEY
   npx wrangler@4 secret put DEEPSEEK_MODEL
   npx wrangler@4 secret put APP_ACCESS_TOKEN
   ```

   `DEEPSEEK_MODEL` 填当前账号实际可用、支持 JSON 输出的模型 ID。不要盲抄旧模型名。`APP_ACCESS_TOKEN` 是另外生成的至少 32 位随机访问码，**不是** DeepSeek 密钥；只供你自己的手机使用。
4. 在 App「设置 → AI 分析」填写部署返回的 HTTPS 根地址（不要加 `/analyze`）、服务访问码和年龄范围，勾选授权并保存。起床补记睡眠时生成分析；已补记的睡眠可用页面上的轻量生成按钮验证一次。
5. 检查生成内容与本机小时数、记录时刻吻合，并核查深度分析证据；先用脱敏测试记录。不要把“模拟测试通过”当成已完成线上验证。

当前 Worker 仅开放 `POST /analyze`，要求访问码；限制 JSON 大小、块数与输出长度，服务限流每 60 秒 5 次。Cloudflare 限流并非全局精确预算锁，必须另外管理 DeepSeek 余额/额度；访问码泄露应立即轮换。服务无数据库、不主动记录日记或调用内容，第三方处理与保留政策以 Cloudflare / DeepSeek 实际条款为准。

本机访问码不写入备份，但保存在 WebView 本地存储，不是 Keychain。正式上架前应改为用户级认证、可撤销短期会话与安全存储，并完善隐私政策、AI 第三方数据告知、费用/配额及商店审核材料。当前并未部署服务器、发布 App Store 或更改你的账号收费设置。

## 知识与安全边界

`knowledge.js` 是仅服务端使用的精简知识文档，涵盖睡眠、节律、光照、葡萄糖、饭后步行、活动、咖啡因和注意切换。保留原始来源、证据类型与局限，UI 无知识库入口、无消息列表。

这是初步的证据摘要，不是完整医疗知识库，也没有宣称收录某位博主的全部知识。原先网页导出 skill 中的若干强断言没有沿用到原生助理。模型仍可能出错：白名单保证来源地址来自审核列表，**不等于已自动核实每句生成内容**。正式上线需对生成建议进行系统性人工评估。

模型收到记录、起床到起床的本机统计、计划对照、年龄范围与时区；不会获得通讯录、位置、HealthKit 或屏幕使用数据。名称与备注按不可信输入处理。没有记录只能说可能漏记，不能说用户没吃饭、没运动或患病。生物学解释不应替代诊断和治疗。

参考接口文档：[DeepSeek JSON 输出](https://api-docs.deepseek.com/guides/json_mode/)；[Cloudflare Rate limiting](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/)。具体健康来源写在 `knowledge.js` 每条记录中。

## 当前行为与已知限制

- 昨日统计：连接跨午夜的睡眠块，以最近两段主要睡眠的结束点为边界；连续3小时以上、跨午夜或清晨3–12点结束且至少30分钟的睡眠作为候选。短睡也能显示，但这仍是记录启发式，不是生理检测；分段睡眠、轮班或补录不足需要后续完善。未找到上次起床时明确提示统计边界缺失。睡眠数字是昨晚这一段，不是自然日睡眠加总；混合事项按种类均分。
- 日报在新鲜的睡眠结束记录保存后生成；手动重试为补漏入口。缓存跟随实际记录和计划历史指纹，编辑旧记录不会每次打开重复扣费；失败不自动无限重试。
- 周报仅本地周日 14:00 后打开助理时生成，只有本周数据，不编造跨周习惯。
- “计划与待办复盘”默认两句：主要偏差、今天接手；完整计划对照折叠。不把“无对应记录”判成失败。旧版本没有留下的计划不伪造复盘；待办删除/反复勾选的完整历史未追踪。
- 通知只保留最近 60 项计划，打开 App、编辑或导入记录时滚动更新；不足 10 分钟的新计划尽快提醒一次。改期取消旧提醒，已提醒的不重复安排。支持循环计划，最长提前扫描 112 天。长期不开 App 的远期计划可能尚未排入。
- 作息提醒是当天手动启用的事件规则，可以启用多条。刚结束吃饭/较长学习/睡眠记录时触发，**不是手机自动检测真实活动**。通知可选“开始”“5 分钟后”“今天不提醒”；超过 15 分钟不再执行，最多延后一次。开始时本机检查空档，才新建短计划。为避免重复，在“开始”创建的即时小计划不再额外弹一次提前提醒。
- 待办采纳只添加暂估半小时计划，不等于勾选完成；不占用已有实际或计划块。
- 新增通知插件已加入 iOS 工程。仍需真机验收：授权/拒绝、锁屏、专注模式、退后台、改期取消、重复计划、跨午夜、通知动作及重启后的去重。浏览器中的插件模拟测试不是系统通知实测。
